# BLISA manuscript code

Reproduce the manuscript's Xenium, Visium, aligned-platform and three-method
benchmark analyses, then draw the main and supplementary figure panels.

The workflow is **starting data → preprocessing → inference → summaries and
comparisons → plotting**. Plotting reads saved analysis results and processed
expression/geometry. Heatmaps compute their clustering when drawn, and native
Xenium CCI maps calculate dominant cell pairs from the saved hotspots and group
counts. Jaccard, pathway analysis, regional coverage and correlations are computed
beforehand; plotting never reruns permutation inference.

Git tracks code, documentation, `software_versions.csv`, `Data/data_sources.csv`,
`Data/downloaded/` and `Data/parameters/`. Generated data, all results, figures,
PDFs and the private `METHODS_writing_reference.md` remain local. Local exclusions
are stored in this checkout's `.git/info/exclude`; no `.gitignore` is published.
These local exclusions do not travel with a clone. Before committing from a new
clone, add the same generated/private paths to its `.git/info/exclude`. Generated
folders are created by the scripts, so they may be absent in a fresh checkout.

## Starting data and software

Download the two original release objects outside the repository:

- [Xenium breast cancer, section 1 replicate 1](https://github.com/ChenLaboratory/example_data/releases/download/v1.0.0/spe_xenium_bc_s1rep1.rds)
- [Visium breast cancer, section 1](https://github.com/ChenLaboratory/example_data/releases/download/v1.0.0/spe_visium_bc_s1.rds)

The other starting references and registration parameters are included under
`Data/downloaded/` and `Data/parameters/`; their sources are recorded in
`Data/data_sources.csv`. The transform CSV and calibration JSON are transcriptions
of published information, not files generated by alignment.

Use the versions in `software_versions.csv`. The original R environment was
R 4.4.2 with BLISA 1.0.2. Benchmark Python environments used Python 3.8.19 with
stLearn 0.4.12 and SpatialDM 0.2.0 respectively; AnnData input conversion used
anndata 0.9.2. Python plotting uses numpy, pandas, matplotlib, scipy and
scikit-image. R scripts name their package dependencies when loading them.

On the original cluster, load the R/system libraries with:

```bash
module load gdal geos proj/9.4.0 mariadb-connector-c/3.3.10 glpk/5.0 ImageMagick/7.1.1 R/4.4.2
```

From the repository directory, configure the release files and interpreters:

```bash
export CCC_XENIUM_RDS=/path/to/spe_xenium_bc_s1rep1.rds
export CCC_VISIUM_RDS=/path/to/spe_visium_bc_s1.rds
export CCC_STLEARN_PYTHON=/path/to/stlearn/environment/bin/python
export CCC_SPATIALDM_PYTHON=/path/to/spatialdm/environment/bin/python
export CCC_PYTHON=/path/to/plotting/environment/bin/python
```

Alternatively, `CCC_SOURCE_DATA_DIR` can identify the directory containing both
release filenames. `RSCRIPT_BIN` defaults to `Rscript`; `CCC_PYTHON` defaults to
`python3`. The method-specific Python paths are required for benchmark analysis,
including reuse of saved method results: the stLearn environment converts inputs
to AnnData, and the SpatialDM environment runs the Visium comparison script.
Release files are not downloaded automatically or copied into this repository.

## Run the workflow

```bash
bash codes/run_workflow.sh all     # Analysis, summaries and figures
bash codes/01_run_analysis.sh all  # Analysis and summaries only
bash codes/02_make_figures.sh all  # Plot already generated data/results
```

To regenerate preprocessing, BLISA results, comparisons and figures while
reusing completed stLearn/SpatialDM results:

```bash
bash codes/run_workflow.sh all --reuse-stlearn-spatialdm
# Or omit figure generation:
bash codes/01_run_analysis.sh all --reuse-stlearn-spatialdm
```

This option still creates the Python input files, but skips the two methods'
inference scripts. It requires their existing local results and resource rows
under `res/benchmarks/`. BLISA saves its own native RDS and updates its rows in
the shared summary/resource tables; saved stLearn/SpatialDM rows are retained.
The method comparison stages then read those results alongside the new BLISA
results. The option does not import or manufacture missing results.

Omitting the argument also selects `all`. Replace it with `xenium`, `visium`,
`aligned_comparison`, `xenium_benchmark` or `visium_benchmark` to run one part.
Without the reuse option, analysis reruns all selected methods, including the
expensive stLearn and SpatialDM inference. The plotting launcher does not run
inference or generate missing analysis summaries.

Both benchmarks depend on the corresponding standalone preprocessing:

- Xenium directly reads `Data/generated/xenium/xenium_50um_binned.rds`, preserving
  `DCIS_1`/`DCIS_2` labels. There is no separate benchmark binning or RDS copy.
- Visium `01a` reads `Data/generated/visium/visium_qc_counts_gt3000_annotated.rds`,
  reuses QC, coordinates and annotations, sums duplicate gene symbols and selects
  the benchmark's single-subunit LR candidates. It retains the historical
  18,082-gene benchmark input without repeating QC or ROI registration.

Xenium runs `01a` count/coordinate export and `01b` AnnData conversion; Visium
runs those steps as `01b` and `01c`, after its `01a` preparation. Both then run
`02` BLISA, `03` stLearn, `04` SpatialDM and `05` method comparison; the reuse
option skips `03` and `04`. `all` prepares the standalone inputs once before the benchmarks.
When selecting a benchmark alone, prepare its standalone input first. Method
runs are sequential because they update shared summary and resource tables.

To refresh summaries from existing inference results without rerunning the
methods, execute the corresponding final analysis script directly:

```bash
Rscript --vanilla codes/analysis/xenium/03_summarize_xenium_lri_cci.R
Rscript --vanilla codes/analysis/visium/04_summarize_visium_lri_pathways.R
Rscript --vanilla codes/analysis/aligned_comparison/04_compare_aligned_lri.R
Rscript --vanilla codes/analysis/benchmarks/xenium/05_compare_xenium_methods.R
"$CCC_SPATIALDM_PYTHON" codes/analysis/benchmarks/visium/05_compare_visium_methods.py
```

## Results and figures

`Data/generated/` holds processed expression, spatial annotations, geometry and
LR candidates. `res/` holds LRI/CCI results, method comparisons, manuscript
statistical summaries and resource measurements.

Standalone Xenium saves `res/xenium/xenium_blisa_result.rds` directly from
`blisa()` and `res/xenium/xenium_lri_regional_coverage.csv` from the summary step.
The processed input retains counts, counts by cell type, cell annotations and
ROI geometry. Figure 2 and S1–S3 read the native result directly; spatial CCI maps
use `blisa::plotCCIspatial()` with the processed group counts. No separate local
LRI, CCI-score or dominant-pair CSVs are generated for this analysis.

Standalone Visium saves `visium_blisa_result.rds` and the native
`visium_blisa_pathway_result.rds` under `res/visium/`, together with regional
coverage, manuscript-text sharing/network summaries and resource measurements.
Pathway aggregation runs in analysis. Figure 3a–e and S4 read these objects and
the processed input directly.

The aligned analysis saves `visium_blisa_result.rds` and
`xenium_blisa_result.rds` under `res/aligned_overlap/`. Its comparison step
writes hotspot counts, their Spearman correlation and spot-level agreement as
CSV files for Figure 3f–h and S5.

Both benchmarks save native BLISA objects:
`res/benchmarks/xenium/xenium_benchmark_blisa_result.rds` and
`res/benchmarks/visium/visium_benchmark_blisa_result_10000_samples.rds`.
No duplicate BLISA local-result CSV is generated. Python comparison/plotting
reads these R objects through temporary tables; the Visium Python entry points
therefore also require `RSCRIPT_BIN` (default `Rscript`). These tables only
reshape saved tests and are not additional analysis results.

stLearn and SpatialDM retain reusable local CSVs, with one LR pair × spot/bin
per row: p-value, test availability and significance. stLearn also retains its
native `lr_score`; SpatialDM's redundant generic score is omitted. These files
remain unsplit and gzip-compressed. Older Xenium caches may contain BLISA rows;
the readers ignore those rows and use the native RDS. Missing or untested
results remain distinct from tested results with zero hotspots.

Benchmark comparison CSVs contain per-LR Jaccard, pooled Jaccard and regional
coverage. Pooled Jaccard divides the summed intersections by the summed unions
over shared eligible LR pairs. Regional coverage divides significant-location
counts by all locations in the region. Pathway and aligned-platform comparison
results are saved in their corresponding `res/` folders.

| Plotting entry point | Panels |
| --- | --- |
| `01_plot_xenium_results_Figure2_FigureS1_S3.R` | Figure 2; S1–S3 |
| `02_plot_visium_results_Figure3a_e_FigureS4.R` | Figure 3a–e; S4 |
| `03_plot_aligned_results_Figure3f_h_FigureS5.R` | Figure 3f–h; S5 |
| `04_plot_xenium_benchmark_Figure4a_c_g_FigureS6_S8a.R` | Figure 4a–c,g; S6; S8a |
| `05_plot_visium_benchmark_Figure4d_f_h_i_FigureS7_S8b_c.R` | Figure 4d–f,h–i; S7; S8b–c |

Files are written as `Figures/figure3a.pdf`, `figure3b.pdf`, etc. Figures 3, 4,
S4, S5, S7 and S8 remain individual panels; S1–S3 and S6 retain their multi-map
layouts. No assembled supplementary PDF is generated. Figure 3f has no overlap
outline or frame; the manuscript outline is added manually in BioRender.
Panels are drawn from data and results, never extracted from existing PDFs.

## Recorded settings and reproducibility

Comparisons use native BLISA calls, stLearn **BH-adjusted** local p-values and
SpatialDM **permutation** p-values. SpatialDM retains its global BH < 0.1
selection step before local p < 0.05 testing; the unused global-result CSV is
not exported. Other stLearn/SpatialDM modes are excluded.

The executed standalone and aligned BLISA calls use `nsim = 9999` and four
threads. Benchmark calls use 10,000 samples and 10 CPUs for Xenium or 40 for
Visium. These are distinct workflows: standalone Visium preserves 18,085 native
feature rows, while benchmark preprocessing collapses duplicate symbols to
18,082 genes. Both retain the same 4,412 QC spots. Visium benchmarking preserves
seed 20260915, its two stLearn distance groups and pooled within-spot BH adjustment.

On 15 October 2026, `01_run_analysis.sh all --reuse-stlearn-spatialdm` completed
from the release inputs, regenerating preprocessing, all BLISA analyses and
comparison summaries. The cached stLearn/SpatialDM results were preserved.
Post-run validation passed all 164 input/result checks and nine cache/scope
checks. Counts and identifiers match exactly; derived coordinates and numeric
annotations allow rounding differences within a 1e-12 tolerance.

BLISA resource rows now describe this fresh run. Retained stLearn/SpatialDM
timing/RAM rows describe their original runs and measurement scope. Rerunning a
method replaces its measurements with values from the current machine.

The native-result readers and analysis summaries were checked against archived
runs. Temporary plotting checks produced all 39 expected PDFs across the
standalone, aligned and benchmark workflows. Their first-page renders were
pixel-identical to the archived panels at 72 dpi, including the S8c dendrogram
and runtime/RAM labels. Those plotting checks used archived inference results.
On 15 October 2026, `02_make_figures.sh all` also regenerated all 39 PDFs from
the fresh analysis outputs. PDF readability and file checks passed; SHA256 checks
confirmed that plotting left all input data and analysis results unchanged.
Figure 4d's low-runtime label is raised slightly to keep both lines inside its
frame. The PDFs are saved locally under `Figures/`.

The original Xenium workflows did not record an explicit random seed. Xenium
SpatialDM retains its native Figshare database download inside the timed stage,
and Xenium BLISA retains its native database loader. The shared CellChat input
is frozen, but the precise historical native database downloads were not
archived; bit-for-bit inference reproducibility is therefore not established.
The fastLISA 1.0.1 entry records the verified local reproduction environment;
its independent version was absent from the historical aligned session report.

S1–S3 layouts were reconstructed from the existing combined reports. Their
original assembly/dendrogram-order provenance remains unresolved; this is
separate from reproducing their data and native hotspot calls.
